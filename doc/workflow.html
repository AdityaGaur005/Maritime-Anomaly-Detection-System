0Big Picture — Two Phases
The project has an offline training phase and an online serving phase. Training runs once; serving runs continuously.

Phase 1 — Offline Training

Runs once on historical AIS data (Hawaii 2017–2020). Produces model weight files saved to disk. Nothing in this phase is time-sensitive.

Phase 2 — Live Serving

FastAPI server loads the trained models and scores incoming AIS broadcasts in real time. A WebSocket consumer feeds live data from aisstream.io.

4Core Inference — POST /predict (per request)
Every single AIS broadcast goes through this entire path. The first 30 points per vessel return "warming up"; point 31 onwards returns a live anomaly score.
Incoming HTTP POST /predict
{ MMSI, lat, lon, speed_over_ground_knots, course_over_ground_deg, datetime_hst }
Pydantic Validation (AISPoint)
lat ∈ [−90, 90] · lon ∈ [−180, 180] · speed ∈ [0, 102.4] · course ∈ [0, 360]
No NaN / Infinity · MMSI non-empty and ≤ 64 chars
invalid → 422 Unprocessable (safe JSON error)
_compute_deltas() — derive kinematic fields
Look up this vessel's last raw point.
First point ever? → store it, return ready: false
Gap < 1 s? (duplicate / out-of-order) → skip, return ready: false
Otherwise compute: computed_speed (geopy distance ÷ time) · acceleration (Δspeed ÷ Δtime) · heading_change (angular diff)
Clamp each value to training-time bounds (no dropping — keeps buffer continuity).
_add_enriched_point() — rolling buffer
Append the 7-field enriched point to _vessel_buffers[MMSI]
Trim to max 60 entries. Buffer is in-memory, lives for the process lifetime.
Buffer length ≥ 30?
The first 30 enriched points (≈ 40 min of AIS at 60 s intervals) warm up the window.
NO — Still Warming Up

Return { ready: false, anomaly_score: null, point_count: N }

YES — Score This Window

Take the last 30 enriched points and continue to feature extraction below.

_extract_features() → 55-element feature vector
Compute all 55 features from the 30-point window + vessel profile.

Runs as a separate process. Connects to live AIS stream and feeds the prediction API continuously.
main() → asyncio.run(_async_main())
Set up logging · Register SIGINT/SIGTERM handlers · Load watchlist · init_db() · Start 3 worker tasks
WebSocket CONNECT to aisstream.io
wss://stream.aisstream.io/v0/stream with compression="deflate" (required from Sept 2026)
Send subscription: { APIKey, BoundingBoxes: [Hawaii], FilterMessageTypes, FiltersShipMMSI }
For each message received…
Route by MessageType
SubscriptionConfirmation
Mark confirmed = True. If this never arrives after 3 reconnects → exit (bad API key)
Static Data (ShipStaticData / StaticDataReport)
Parse vessel type, length, beam → update_static_attributes() → write to SQLite immediately (synchronous, ~1 ms)
Position Report (Class A & B)
1. Validate with Pydantic
2. Reject sentinel values (SOG=102.3, COG=360)
3. Throttle: gap < 60 s? → drop
4. queue.put_nowait(payload)
   Queue full? → drop + log
Worker Tasks (×3 in parallel) drain the queue
await queue.get() → httpx.AsyncClient.post("/predict", json=payload)
200 + is_anomaly:true → log ANOMALY_DETECTED
422 → log validation error · 5xx / timeout → log server error
WebSocket disconnected?
Exponential backoff reconnect: 1s → 2s → 4s → … → 60s max
No SubscriptionConfirmation ×3 → exit · HTTP 401/403 → exit immediately
6Vessel Baseline Learning Over Time
Confidence improves the longer a vessel is tracked. The system starts with fleet-wide averages and gradually learns each vessel's individual behaviour.
First Contact — Cold Start
Vessel seen for the first time. No data in SQLite yet.
Profile returns population fallback (stats from all 2017-2020 Hawaiian vessels).
confidence: "low" · baseline_is_fallback: true
Z-score features compare this vessel against the whole fleet.
1–49 Normal Points Accumulated
Each normal AIS point (score < 0.77) is stored in vessel_sample_points.
Still below the 50-sample threshold — population fallback still used.
Scores are less personalised; anything deviating from fleet average looks anomalous.
50+ Normal Points — Vessel-Specific Baseline Unlocked
Profile now returns this vessel's own mean/std of speed and heading, and its median position (centroid).
confidence: "high" · baseline_is_fallback: false
A fast ferry that always runs at 22 kn looks normal. The same speed for a slow tugboat looks anomalous.
Caps at 2000 stored samples — oldest evicted on overflow.
7How the Three Models Work Together
The two autoencoders act as feature extractors. XGBoost is the final decision maker.
30-point AIS window — shape (30 × 7)
lat · lon · speed · course · computed_speed · acceleration · heading_change
TransformerVAE
Trained only on normal voyages.

Self-attention sees the whole 30-step window at once — good at long-range patterns.

Encode → mu (latent mean)
Decode(mu) → reconstruction
No reparameterize() — deterministic.
8 error values
MSE per channel + aggregate
LSTM Autoencoder
Trained only on normal voyages.

Recurrent memory captures local sequential steps — good at short-range transitions.

Encoder LSTM → latent vector
Decoder LSTM → reconstruction
Standard seq2seq, no teacher forcing.
8 error values
MSE per channel + aggregate
16 deep error features + 39 context features = 55 total
XGBoost — Final Scorer
Trained on labelled data (normal windows vs incident windows).
Learns which error features matter, in which context, for which vessel type.
A high Transformer error alone may not be anomalous — XGBoost weighs all 55 signals together.
Output: single probability score in [0.0, 1.0]
score < 0.85

Normal vessel behaviour

score ≥ 0.85

ANOMALY DETECTED — alert logged

hybrid/train_xgboost_hybrid.py Training (once) Trains XGBoost on the 55-feature table with MMSI-grouped split, saves xgboost_hybrid_final.json
mlops/main.py Serving (always on) FastAPI app — loads models at startup, exposes POST /predict
mlops/feature_factory.py Serving (per request) Per-request pipeline: buffer management → 55-feature extraction → deep model scoring → XGBoost score
mlops/kinematics.py Serving (per request) Pure math helpers: angular difference, value clamping, ISO timestamp parsing

mlops/ais_consumer.py Serving (always on) WebSocket consumer — reads live aisstream.io, validates, throttles, queues, POSTs to /predict
mlops/discover_vessels.py Occasional (one-shot) Listens to stream for N minutes, ranks vessels by activity, writes a watchlist file
pop_fallback.json Serving (cold-start) Fleet-level speed/heading/position stats used when a vessel has fewer than 50 observed points
static_fallback.json Serving (cold-start) Fleet-median vessel type, length, and beam used when no static AIS broadcast has been received
vessel_profiles.db Serving (persistent) SQLite database — per-vessel baselines that accumulate and improve over time
